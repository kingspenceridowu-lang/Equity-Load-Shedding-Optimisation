## For live slider re-solving (capacity / fairness cap)
Import directly rather than shelling out:
```python
from optimizer import load_data, compute_available_capacity, solve_lp
from evaluation import compute_metrics

df = load_data("zones_dataset.csv")
available = compute_available_capacity(df) * your_capacity_slider_value  # 0-1 fraction
status, allocation_df = solve_lp(df, available, max_consecutive_outage_hours=your_fairness_slider)
```
A single solve on this dataset size (20 zones x 48 hours) takes well
under a second, so live re-solving on slider change should be fine for
a demo — but the plan's fallback (precomputed scenarios) is easy: just
call `evaluation.run_sensitivity_check()` with whatever slider values
you want pre-baked and read from `sensitivity_results.csv` if live
solving turns out to be too slow or too fragile right before the demo.

## Important framing note for your charts and narrative
**Do not build a "hospital outage hours" or "critical zone" chart
straight from `served_fraction` or grid allocation alone.** A zone with
strong backup capacity is *correctly* given little grid power by the
optimizer — that's central to the "the system doesn't punish
self-sufficient institutions" pitch point — but a chart that only looks
at grid allocation will show that zone getting *worse* under the
optimized model, which is backwards and will undercut your own pitch if
a judge notices. `results_per_zone.csv` and `results_comparison.csv`
are already computed correctly (actual power = grid allocation +
backup, compared against demand) — use those numbers as-is rather than
recomputing "outage hours" yourself from the raw schedule files.

## Numbers worth building the demo around (current dataset, seed=5)
- Total harm reduced: **66.8%** vs. baseline, using the identical harm
  formula for both.
- Cold storage / water-pumping zones (no backup, criticality 7): denied
  power for the **entire 48-hour baseline horizon**, fully served under
  the optimized model. This is the single most visceral before/after
  number in the dataset — consider leading with it.
- The partially-backed-up hospital (Hospital_2): 12 outage hours under
  baseline, 0 under the optimized model. The fully-backed-up hospital
  (Hospital_1): 0 either way — useful to show *both*, since together
  they demonstrate the model treats backup status correctly rather than
  just "protects all hospitals."
- Fairness constraint held with zero violations across all 20 zones
  over the full 48-hour horizon — worth stating as a guarantee, not
  just an outcome, in the pitch.
